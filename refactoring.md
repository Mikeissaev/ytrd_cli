# План рефакторинга проекта YTRD

## Цель
Повышение качества кода, отказоустойчивости и поддерживаемости проекта, следуя принципам Clean Architecture и Industrial Best Practices, без изменения текущей функциональности.

## 1. Архитектурные изменения

### 1.1. Устранение циклических зависимостей
*   **Проблема:** `utils.py` импортирует `cli.py` внутри функций. `vot.py` зависит от `downloader.py`.
*   **Решение (Dependency Injection):**
    *   Удалить импорт `cli` из `utils.py` и `downloader.py`.
    *   В функции, требующие взаимодействия, передавать `callback` для принятия решений.
    *   Вынести логику скачивания из `vot.py`. `vot.py` должен только возвращать ссылку на аудио, а оркестратор (main/controller) вызывать `downloader`.
    *   **Приоритет:** Высокий.

### 1.2. Унификация обработки ошибок
*   **Проблема:** Использование `sys.exit(1)` в глубине модулей (`downloader.py`, `utils.py`).
*   **Решение:**
    *   Создать базовую иерархию исключений в `errors.py` (например, `YtrdError`, `NetworkError`, `ExternalToolError`). Не переусложнять иерархию.
    *   Заменить все `sys.exit()` на `raise CustomError`.
    *   Обрабатывать исключения только на верхнем уровне (в `main.py` или `cli.py`).
    *   **Приоритет:** Самый высокий (делать в первую очередь).

### 1.3. Логирование
*   **Проблема:** Использование `print()` для всего.
*   **Решение:**
    *   Внедрить модуль `logging`.
    *   Внутри модулей использовать обычный `logger`.
    *   Цвета и форматирование оставить только на уровне CLI (или через `logging.Formatter` в точке входа). `rich` подключать опционально и позже, чтобы не переусложнить.
    *   **Приоритет:** Средний.

## 2. Рефакторинг модулей

### 2.1. Модуль `vot.py` (Yandex Voice-Over Translation)
*   **Изоляция Protobuf:**
    *   Скрыть ручную реализацию Protobuf в отдельный класс-хелпер (не генерировать код `protoc`).
    *   Упростить чтение бизнес-логики `translate_video`.
*   **Класс `VotClient`:**
    *   Обернуть функции в класс `VotClient` (хранение сессии `requests.Session`, заголовков).
    *   **Приоритет:** Высокий.

### 2.2. Модуль `downloader.py`
*   **Разделение ответственности:**
    *   Использовать простые колбэки (`progress_callback(percent, speed)`) вместо жесткой привязки к `tqdm`.
    *   Это позволит в будущем легко подключить другой UI или headless-режим.
    *   **Приоритет:** Средний.

### 2.3. Модуль `utils.py`
*   **Очистка:**
    *   Превратить в набор чистых функций.
    *   Все интерактивное убрать в `cli`.
    *   Функции, зависящие от конфига, должны принимать параметры явно.
    *   **Приоритет:** Высокий.

## 3. Кроссплатформенность и пути
*   **pathlib.Path:** Использовать вместо `os.path` для надежности (особенно на Android/Termux).
*   **EnvironmentChecker:** Упростить проверку окружения (простая проверка `shutil.which` для `ffmpeg` с fallback-логикой). Не создавать сложный фреймворк.
*   **Приоритет:** Средний.

## 4. Конфигурация
*   Перейти от глобальных переменных к загрузке конфигурации в объект (`config = load_config()`), который передается в `main`. Избегать Singleton, если он не критичен.
*   **Приоритет:** Средний.

## 5. Тестирование
*   Обновить тесты. После развязки зависимостей (DI) это станет проще.
*   Использовать `mock` для сети и `yt-dlp`.
*   Добавить тесты для Protobuf-парсера.

## План действий (Step-by-Step)
1.  **Errors:** Создать `src/ytrd/errors.py` и заменить `sys.exit`.
2.  **Decoupling:** Развязать `utils` / `cli` / `downloader` (внедрение callback'ов).
3.  **VOT:** Рефакторинг `vot.py` (Protobuf helper + Client).
4.  **Pathlib & Config:** Внедрение `pathlib` и объекта конфигурации.
5.  **Logging:** Внедрение базового `logging`.
6.  **Features:** UX улучшения (после стабилизации кода).
